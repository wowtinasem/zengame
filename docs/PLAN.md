# 숫자 색칠(Color by Number) 앱 기획·개발 계획

> 참고 앱: Zen Color – 숫자별 색상 (Oakever Games). 장르와 게임 방식만 참고하고,
> 이름·그림·로고·음악 등 그 앱의 에셋은 쓰지 않는다. 그림은 전부 직접 만들거나 라이선스를 받은 것을 쓴다.

**장르 시장 포인트**
- 2020년 이후 경쟁 앱이 크게 늘면서 장르 수익이 **광고 위주**로 바뀌었다. IAP는 보조 수단이다.
- 선두 앱(Happy Color)은 IP 콜라보와 시즌·이벤트 콘텐츠로 차별화한다. Zen Color는 **아트 퀄리티와 "힐링" 무드**로 차별화했고, 2024년부터는 미국 설치 수에서 Happy Color를 넘어섰다는 보도도 있다.

## 2. 우리 앱의 방향 (제안)

- **가칭:** 정해야 함 (예: "Calm Canvas", "고요색칠"). 레퍼런스와 헷갈리는 이름은 피한다.
- **콘셉트 후보** (하나 고르기)
  1. 한국적 힐링: 한옥, 사찰, 산수화, 민화, 사계절 풍경 (차별화 포인트가 뚜렷함)
  2. 수채화 감성의 자연·식물 일러스트
  3. 시간대·날씨에 따라 바뀌는 "정원 키우기" 메타 게임과 결합
- **타깃:** 25~55세 여성 비중이 높은 캐주얼·힐링 유저

## 3. 핵심 기능 (MVP 범위)

### 게임플레이
- 그림이 숫자가 적힌 영역으로 나뉘고, 하단 팔레트에서 색(번호)을 골라 해당 영역을 탭하면 칠해진다
- 핀치 줌과 팬. 확대해야 작은 영역의 번호가 보인다
- 선택한 번호의 영역을 하이라이트(회색 음영)하고, 다 칠한 색은 팔레트에서 체크로 표시한다
- 드래그 칠하기: 길게 누르고 문지르면 같은 번호 영역이 연속으로 칠해진다
- 힌트: 남은 영역 위치로 카메라를 이동한다 (광고 시청이나 재화로 사용)
- 완성하면 칠한 순서대로 재생되는 타임랩스 애니메이션을 보여주고, 영상이나 이미지로 저장·공유할 수 있다
- 진행 상황 자동 저장 (중간에 나가도 이어서 하기)

### 메타 / 화면
- 홈: 카테고리별 그림 피드 (풍경, 꽃, 동물, 만다라, 신규, 인기)
- 데일리 그림 (매일 1장, 재방문 유도)
- 내 작품 (진행 중 / 완료)
- 설정: 배경음악·효과음, 진동, 다크 모드, 번호 하이라이트 옵션

### 2차 (MVP 이후)
- 이벤트·시즌 컬렉션, 스토리형 챕터
- 사진을 업로드하면 숫자 색칠 도안으로 변환하는 기능
- 구독(VIP): 광고 제거, 모든 그림 해금, 매주 독점 그림
- 서버 기반 콘텐츠 배포 (앱 업데이트 없이 새 그림 추가)

## 4. 기술 설계

### 4.1 스택 추천: **Flutter** (Android + iOS 단일 코드)
- 2D 캔버스 렌더링(CustomPainter), 제스처, UI 개발 속도 모두 이 앱에 충분하다
- Unity도 가능하지만 UI 위주 앱에는 무겁고 앱 용량이 커진다
- 백엔드: Firebase (Storage 및 CDN으로 그림 배포, Firestore로 카탈로그, Remote Config, Analytics, Crashlytics)
- 광고·결제: AdMob (미디에이션 포함), RevenueCat 또는 in_app_purchase

### 4.2 그림 데이터 포맷 (가장 중요한 설계)
SVG를 런타임에 그대로 렌더링하면 영역이 수천 개일 때 느려진다. 그래서 **미리 가공한 데이터**를 쓴다.

```
artwork_0001/
  meta.json        # id, 제목, 카테고리, 크기, 팔레트[{index, rgb}]
  lineart.webp     # 외곽선 레이어 (고해상도, 투명 배경)
  regions.png      # 영역 ID 맵: 픽셀 RGB = 영역 ID (24bit → 최대 1,600만 영역)
  regions.json     # [{id, colorIndex, bbox, labelPos, labelSize}]
  thumb.webp       # 목록용 썸네일
```

- **탭 판정:** 탭 좌표를 그림 좌표로 변환한 뒤 `regions.png`에서 해당 픽셀의 ID를 읽는다. O(1)이라 아주 빠르다
- **칠하기:** 영역별 마스크를 이용해 채움 레이어에 그리고, 칠한 결과는 비트맵 캐시에 누적한다
- **번호 표시:** `labelPos`는 영역 안쪽에서 가장 넓은 지점(polylabel 또는 distance transform)으로 잡고, 줌 배율 × 영역 크기가 임계값을 넘을 때만 그린다
- **렌더 레이어:** 원본 색 힌트(옅은 회색) → 채움 레이어 → 하이라이트 → 선화 → 번호
- **줌/팬:** 그림 전체에 하나의 변환 행렬을 적용한다. 큰 그림은 타일로 나누고, 화면에 보이는 영역만 그린다

### 4.3 콘텐츠 제작 파이프라인 (Python 툴)
1. 일러스트레이터가 **선화와 완성 컬러본**을 만든다 (벡터 또는 고해상도 PNG)
2. 툴이 선화에서 닫힌 영역을 추출한다 (flood fill / connected components)
3. 각 영역의 대표색을 컬러본에서 뽑아 팔레트로 양자화한다 (k-means, 20~40색)
4. 너무 작은 영역은 이웃 영역에 병합하고, 라벨 위치를 계산한다
5. `meta.json`, `regions.png`, `regions.json`, 썸네일을 출력하고 Firebase에 업로드한다
6. 내부 미리보기 웹툴로 QA한다 (번호 겹침, 칠할 수 없는 영역 확인)

> 이 파이프라인은 나중에 "사진을 도안으로 변환" 기능의 기반이 된다.

### 4.4 앱 구조 (Flutter)
```
lib/
  core/        # 라우팅, DI, 테마, 로컬 저장(Hive/Isar)
  data/        # 카탈로그 API, 그림 다운로드/캐시, 진행 저장
  features/
    home/      # 피드, 카테고리, 데일리
    coloring/  # 캔버스 엔진, 팔레트, 제스처, 힌트
    gallery/   # 내 작품
    complete/  # 타임랩스, 공유
    settings/
  monetization/ # 광고, IAP, 구독
```

## 6. 일정 (1~2인 개발 + 일러스트 외주 기준, 약 4~5개월)

| 단계 | 기간 | 산출물 |
|---|---|---|
| 0. 기획·아트 방향 | 2주 | 콘셉트 확정, 앱 이름, 아트 스타일 가이드, 샘플 그림 3장 |
| 1. 프로토타입 | 3주 | Python 도안 툴 v1 + Flutter 캔버스(탭 칠하기, 줌, 번호 표시). **손맛 검증** |
| 2. MVP 개발 | 6주 | 홈·갤러리·저장·완성 연출·설정, 로컬 그림 30장 |
| 3. 서버·수익화 | 3주 | Firebase 카탈로그와 다운로드, AdMob, IAP, 애널리틱스 |
| 4. 베타 | 2~3주 | 내부/비공개 테스트, 저사양 안드로이드 성능 튜닝, 그림 100장 확보 |
| 5. 출시 | 1주 | 스토어 등록(ASO: 스크린샷, 키워드), 개인정보처리방침, 등급 심사 |
| 운영 | 지속 | 주 10~20장 신규 그림, 이벤트, 지표 기반 개선 |
